01 One codebase, two products

XELOR is not a fork of ONYX and does not replace it. It reads ONYX's records and writes back through ONYX's own endpoints, so the two run side by side on separate ports and separate databases from a shared pnpm workspace.

03 Repository shape

apps/api

modules/ one folder per business domain · agent-os/ the agent runtime · ai/ router and features · bus/ outbox relay and queues · ports/ the only legal cross-module doorways · fulfilment/ missions, XELOR only.

apps/web

modules/ mirrors the API one-for-one, assembled by a single registry.ts · spine/ shell, navigation and copilot driver · scripts/ the PDF render pipeline.

packages/

platform — domain logic with no NestJS and no database: registries, graph validation, hash chains, tax, planning, confidence. db — Drizzle schema, migrations, tenant-scoped connections.

Module boundaries are a lint rule, not a convention — eslint-plugin-boundaries fails CI. No module imports another's service and no foreign key crosses a boundary. Everything goes through a typed port — STOCK, BOM, WORKFLOW, CUSTOMER_ORDER_WRITER — or a versioned event. Production may never write stock: the single write path POST /api/v1/stock/entries belongs to Inventory alone.

04 How one request moves

Every write in both products follows the same eight steps. Nothing skips a step, including anything an agent initiates — an agent is just another authenticated caller.

01 · WEB
Next.js
Server component or client action calls api/v1 with the user's bearer token.
02 · GUARD
Identity
jose verifies the Keycloak JWT — issuer, audience, expiry.
03 · GUARD
Tenant & RBAC
Middleware binds the tenant; the permission guard requires all declared permissions.
04 · DATA
RLS transaction
Drizzle runs under SET LOCAL app.current_tenant; Postgres enforces the row filter.
05 · WRITE
Domain + outbox
The business rows and the event row are written in one transaction, so neither can exist alone.
06 · AUDIT
Hash chain
A field-level change set is hashed onto the previous entry, per tenant. Any edit breaks the chain.
07 · RELAY
Outbox → BullMQ
A relay claims batches with FOR UPDATE SKIP LOCKED and enqueues by event id.
08 · CONSUME
Idempotent worker
At-least-once delivery plus idempotent handlers gives exactly-once effect.

The write contract

UUIDv7 primary keys · tenant_id on every tenant-scoped table with composite indexes leading on it · created_at/by, updated_at/by, is_active soft delete · no hard delete on master, financial or statutory rows · money as NUMERIC(18,2) · effective-dated rate masters · one canonical error envelope · cursor pagination only · Idempotency-Key on every mutating endpoint.

The event contract

Versioned names — module.entity.verb.v1 — published only through the transactional outbox. The relay drains per tenant under that tenant's RLS context, so the bus never becomes a way around the row filter. Ledger-critical writes never travel on the bus: they stay synchronous inside the one transaction that produced them.

05 How the AI is connected

No business module ever talks to a model. Every call passes through one router, which does exactly four things before and after the provider — and contains no business logic.

STEP 1
Reject the unregistered
The feature key must be in the closed registry — nine routable features plus one explicit "no AI here" entry. Anything else throws.
STEP 2
Ask governance
Kill switch, tenant opt-out and budget are checked before a token is spent. A refusal is itself logged, then fails closed.
STEP 3
Route to a provider
Offline stub in development, a local Ollama model on a workstation, a hosted model in production. Swapping one changes no caller.
STEP 4
Log it, chained
Input, output, model, tier and token usage append to the hash-chained ai_action_log. Refusals included.

The closed registry

Each entry carries a risk tier and a degraded mode the feature drops to when AI is off or refused: receipt extraction and duplicate-receipt detection, master-data dedup, HSN/SAC suggestion, ticket triage and reply drafting, payslip and segregation-of-duties explainers, copilot retrieval QA. Degraded modes are real paths — manual_entry, deterministic_substitute, template_output, feature_hidden — not error screens.

Two gates before a model ships

The eval gate grades the detector against a golden set — pnpm eval general.master_dedup must clear its F1 threshold. The grounding gate grades the explanation: every conclusion must match the code-decided verdict, no sentence may contain a value absent from the evidence, and no note may contradict its own headline. Both exit non-zero, so CI blocks a provider that is not safe to ship.

07 The copilot pipeline

The copilot is retrieval-first and deterministic: the model is the last step, not the first, and it may rephrase — never compute.

01
Route
The question is matched to a registered intent with typed parameters.
02
Authorise
The asker must hold that intent's own permission. The copilot never shows what their access would not.
03
Retrieve
A registered SQL query runs under RLS with a row cap — not generated SQL.
04
Render
Rows, sources and an as-of timestamp are formatted deterministically.
05
Narrate, then check
Optional prose is verified against the rows and discarded if it drifts.

08 The graph, and the loop that walks it

A graph is an auditable execution plan, not a prompt. Eight are registered — foundation mission, factory flow and factory intelligence recovery, full command review, controlled action, working-capital review, QMS audit readiness, managed-service assurance. A model may supply a node's structured output; it can never invent a node, an edge, a permission or a side effect.

Six node kinds

agent reasons · capability calls one of 20 registered tools · transform joins evidence · branch chooses on a condition · approval stops for a person · verification re-checks the boundary. Every capability is graded read, analyse, simulate, draft or execute.

Validated before it runs

validateAgentGraph rejects a cycle, a dangling dependency, a branch with no source, or a node asking for more than five attempts. Each node carries its own status — pending, running, waiting_approval, succeeded, failed, skipped, cancelled — so a run is inspectable at any moment.

A capability is a contract, not a call

Each of the 20 declares the permission it needs, the agents allowed to hold it, a Zod parser for its input, whether it has side effects, whether it needs approval, and an execution boundary of domain_service — so it reaches data through the very same module service a person's request would, never through SQL of its own.

An agent runs as the person who launched it

Internal tool calls skip the controller guard, so the RBAC check is repeated inside the runtime against the operator's own roles, under their tenant's RLS context. An agent can narrow a user's authority; it can never widen it.

Two refusals, two behaviours

An operator lacking a permission (AGENT_TOOL_FORBIDDEN) only skips that node — people legitimately see different things. A graph naming a capability its agent may never hold (AGENT_CAPABILITY_FORBIDDEN) fails the run loudly: a static misconfiguration, identical for everyone.

Confidence rates evidence, not odds

Every decision carries a deterministic score across evidence coverage, freshness, completeness and learning history, with its strengths and gaps named. It never claims a probability that the proposed action will work.

Down to the line

apps/edge runs beside the machines behind adapters for simulator, OPC UA, MQTT, ROS 2 and vendor controllers. It reads state — running, idle, blocked, faulted, protective stop, offline — and executes exactly six capabilities: enqueue a robot job, select an approved program, pause after cycle, dispatch an AMR route, quarantine output, request an inspection.

Bounded by clocks, not by trust

Commands are fingerprinted with SHA-256 and single-flighted, so a duplicate key cannot fire twice. A command expires in 15 minutes, telemetry older than 2 minutes is stale, and an approval older than 15 minutes authorises nothing. Safety is asked of the local adapter immediately before execution, never inferred.

The rule the whole architecture exists to keep: AI explains, it never decides. Nothing reaches a customer, a supplier, a ledger or a machine without a person approving it, and every approval is reconstructable afterwards — the cited rows, the model call, the permission held, and the hash chain proving none of it was edited since.
